# SAMS — คู่มือการใช้งาน (User Manual)

ระบบบริหารจัดการการเข้าเรียนผ่าน QR Code — คู่มือนี้เขียนตามหน้าจอและพฤติกรรมที่ทดสอบจริง

## หน้าเข้าสู่ระบบ

- URL: `/login` — กรอก **ชื่อบัญชี / รหัสผ่าน** แล้วระบบพาไป dashboard ตามบทบาทโดยอัตโนมัติ
- ปุ่มตัวอย่างบทบาท (admin / instructor / student) ใส่ username ตัวอย่างในฟอร์มเพื่อทดลองเร็ว (dev)
- เข้าสู่ระบบสำเร็จ → ระบบเก็บ access token ในหน่วยความจำเบราว์เซอร์ (ไม่มีใน localStorage) ส่วน refresh อยู่ใน cookie ปลอดภัยของเซิร์ฟเวอร์เท่านั้น
- เมื่อ access token หมดอายุ ระบบต่อ session ด้วย refresh ตัวเองแบบอัตโนมัติ — reload หลายครั้งไม่ต้อง login ใหม่ (ทดสอบ reload ×2)
- ออกจากระบบได้จากเมนูบนหน้า dashboard ทุกบทบาท (ทดสอบ logout สำเร็จจริง)

---

## 1. Administrator (ผู้ดูแลระบบ)

เมนู `/admin/*` ด้านซ้าย ประกอบด้วย: **Dashboard, Users, Students, Instructors, Programs, Class-Groups, Academic Terms, Courses, Course Offerings, Enrollments, Schedules, Attendance Sessions, Attendance Records, Reports, Audit Logs**

### Dashboard
- สถิติรวม (การ์ดตัวเลข + กราฟ — ทดสอบจริง render กราฟ 2 ชุด)
- ตาราง users แสดง 11 รายการ (ตามข้อมูลจริงในฐานข้อมูล)

### Users
- เพิ่ม/แก้ไข/เปิด-ปิดใช้งานบัญชี (role: admin / instructor / student)
- **นำเข้านักศึกษาด้วย CSV**: ฟอร์มอัปโหลดไฟล์ `.csv` ผ่านช่องอัปโหลด แล้วกดยืนยัน
  - ระบบ sanitize สูตรในไฟล์อัตโนมัติ (เช่น `=HYPERLINK(...)` ถูกแปลงเป็นข้อความกัน formula injection — ทดสอบจริง)
  - ทุกแถว validate จากระบบ: รหัสนักศึกษาซ้ำถูกปฏิเสธ (จริง: `student_id_code` unique)

### Reports
- ตารางรายงานข้อมูลการเข้าเรียนรวม + **ปุ่ม Export CSV** → ไฟล์ดาวน์โหลดแบบ UTF-8-BOM เปิดใน Excel ภาษาไทยถูกต้อง (ยืนยัน bytes ของไฟล์จริง)

### ทุกหน้าตาราง (Users / records / sessions / audit logs)
- Generic table พร้อม pagination: แถว + สร้าง/แก้ไข/ลบ, แต่ record ที่เกี่ยวข้อง (audit, attendance เข้าแล้ว) จะถูกบล็อกไม่ให้แก้/ลบโดยตรง — และถ้าแก้ attendance record ต้องระบุ **edit_reason** (เหตุผลการแก้) ก่อนบันทึก

## 2. Instructor (อาจารย์)

เมนู: **Dashboard, Courses, Schedule, Attendance**

### Dashboard
- ตรวจสอบคาบของตัวเองทั้งหมด + ข้อมูลปุ่มเข้ายัง/เปิดคาบ

### Courses / Schedule
- รายวิชาที่สอน + ตารางเรียนประจำสัปดาห์ (อ่านจาก course offerings ที่ผูกกับตัวเอง)

### Attendance — ตารางเช็คชื่อ
- รายการคาบตามรายวิชาที่สอน + ปุ่มเข้าหน้า control room (ถ้ายังไม่เปิด ให้กด "เปิดคาบ" ก่อน)

### Control Room — `/instructor/attendance/[sessionId]` ✅ (ทดสอบจริงเต็มรอบ)
หน้าหลักที่ใช้ระหว่างเช็คชื่อ ประกอบด้วย:

1. **QR Code** แสดงเป็น SVG ในหน้า control room — โค้ด **หมุนทุก 30 วินาที** พร้อม countdown วินาทีที่เหลือ (ทดสอบจริง: เห็นข้อความ "5 วินาที" ถัดจากการหมุนรอบถัดไป)
2. **Roster (รายชื่อ)** ทางขวา: รายชื่อนักศึกษา + สถานะ อัปเดตทันทีหลังนักศึกษาสแกน (ทดสอบจริง: 65000001–06 อัปเดตเป็น `present`/`late` เรียลไทม์)
3. **ปุ่มหยุดชั่วคราว (⏸)** → คาบพักชั่วคราว, เปลี่ยนเป็น **▶ เปิดต่อ** → QR หมุนต่อตามเดิม
4. **ปิดคาบ (⏹)** → ระบบสร้าง **absent อัตโนมัติ** ให้คนที่ยังไม่เช็คชื่อ (ทดสอบจริง: 6 รายการเกิดขึ้น)
5. **ยกเลิกคาบ (✖)** → คาบถูกยกเลิก จะไม่นับใน report

### รายงาน
- `/instructor/reports` — ตารางข้อมูลการเข้าเรียนตามคาบ/เทอมที่ตัวเองสอน

## 3. Student (นักศึกษา)

เมนู: **Dashboard, Courses, Schedule, History, Scan, Profile**

### Dashboard
- การ์ดสถิติ + รายการเช็คชื่อล่าสุด (ทดสอบจริง: 16 แถว + 4 การ์ด)

### Courses / Schedule
- รายวิชาที่ลงทะเบียน + ตารางเรียนของตัวเอง

### Scan (โหมดสแกน)
- เปิดกล้องสแกน QR (html5-qrcode) — แต่ละ token มีอายุ **30 วินาที** ให้สแกนทันทีที่หน้าจออาจารย์หมุนรอบใหม่
- มีโหมดกรอก **รหัส (token) ด้วยมือ** (กรณีกล้องไม่ได้/หน้าจอขอเช็คชื่อด้วย token)
- สแกนสำเร็จ → record `present` (หรือ `late` ถ้าเกินเวลาเริ่ม + threshold)
  - ทดสอบจริง: กรอก token → check-in สำเร็จ
  - Check-in ซ้ำ → แจ้งเตือน **"คุณเช็คชื่อในคาบนี้แล้ว"** (409) — ทดสอบจริง
  - Token หมดอายุ → แจ้งเตือน (กลับๆ ไปต้องสแกน QR ครั้งล่าสุดที่หน้าจออาจารย์อีกครั้ง)

### History
- ประวัติการเช็คชื่อของตัวเอง (เฉพาะ records ของตัวเอง)

### Profile
- ข้อมูลโปรไฟล์และ **ข้อข้อมูลส่วนบุคคลแบบอ่านอย่างเดียว (PDPA read-only)** — ตัวนักเรียนแก้ในแอปไม่ได้ ติดต่อเจ้าหน้าที่แทน

## ขอขอบพระคุณ / เปลี่ยนบัญชี

- ออกจากระบบ (Logout): ระบบลบ cookie refresh และ blacklist token ทันที
- ถ้า session หมด (401) และเรียก refresh ไม่สำเร็จ จะถูกพาไปหน้า login ตามเดิม
